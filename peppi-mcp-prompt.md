# PeppiMCP Implementation Prompt

I'm building a Slippi replay MCP server that I want to call "peppi-mcp". Start by doing research on the following topics:
MCP (model context protocol)

- JuliaBench/ClaudeMCPTools.jl, A Julia implementation of basic Model Context Protocol (MCP) tools for Claude and other AI assistants
- https://github.com/project-slippi/project-slippi
  - Project Slippi, a project for building a replay/metadata infrastructure for Super Smash Bros Melee
- https://docs.rs/peppi/latest/peppi/
   - Peppi is a Rust parser for .slp game replay files for Super Smash Brothers Melee for the Nintendo GameCube. These replays are generated by Jas Laferriere’s Slippi recording code, which runs on a Wii or the Dolphin emulator.
- https://github.com/jph6366/peppi-jl
   - Julia bindings for the __peppi__ Slippi replay parser, built using Apache Arrow and __jlrs__
   
The goal is to produce a minimal, terse, idiomatic julia MCP server and distribute it to Yggdrasil. Output the recommendations and general guidelines to get started. Present this output in a suitable format for handing over to an Julia programmer for building the server.
I would like to note that I plan to keep this as a simple and minimal specifications

I want two tools:
1. search_replays
2. generate_stats

given a user's replay folder or any directory containing .slp replay files...

- for search_replays I will need a way to search replay files for matching queries based on the user requrest. I want to embed them. I need to create replay-level embeddings by aggregating frame-level embeddings focused on retrieval , and index the embeddings using a vector database.  There are existing embeddings in slippi_ai/embed.py (https://github.com/vladfi1/slippi-ai) are designed for individual game states (frames) rather than entire .slp replay files. This would need to adapt them for replay-level indexing.
- the goal of generate_statsis to provide a set of more useful, accurate, and detailed statistics than what slippi-js currently offers. The stats are targeted towards competitive players, with a notable absence of some "novelty" stats like APM. The output integrates easily with existing data science libraries and can provide indications for where a player should improve, as well as tracking that improvement over time.
